# SeqPage — Chrome 新标签页导航工作台

一个本地优先的个人导航扩展：多导航页面、自定义分区、网站卡片管理、拖拽排序、配置导入导出。
基于 **Manifest V3 + Vue 3 + TypeScript + Vite**，**数据全部保存在浏览器本地，不做任何云同步、不依赖任何后端或外部 API**。

---

## 一、快速开始

### 1. 安装依赖

```bash
cd my-navi
npm install
```

> 项目已内置 `.npmrc`（registry 指向 npmmirror 镜像）以加速国内安装。
> 如需离线构建，请参考文末「离线与受限环境」。

### 2. 构建

```bash
npm run build      # 类型检查 + 生产构建，产物在 dist/
```

### 3. 加载到 Chrome

1. 打开 `chrome://extensions/`
2. 打开右上角 **开发者模式**
3. 点击 **加载已解压的扩展程序**
4. 选择本项目的 **`dist/` 目录**
5. 打开新标签页（`Ctrl+T`）即可看到 SeqPage

> 注意：必须选择 `dist/`，而不是项目根目录。修改代码后重新执行 `npm run build`，
> 然后在 `chrome://extensions/` 点击该扩展的「重新加载」按钮。

## 二、功能说明

### 2.1 多导航页面

- 侧边导航栏展示全部导航页面，显示页面图标、名称与网站数量。
- **页面级操作统一收敛到每项右侧的「页面操作」菜单**：新建 / 重命名·修改图标 / 上移 / 下移 / 删除；
  侧栏不再重复摆一个「新建页面」按钮，也没有独立的「页面管理」弹窗。
- 双击页面名可就地重命名（Enter 保存、Esc 取消），适合只改名字；
  需要同时改图标时走菜单里的「重命名 / 修改图标」。
- 新建页面后自动切换过去；页面数据彼此完全隔离（在「安全运营」删除分区不会影响「开发工具」）。
- **删除页面必须二次确认**，并明确告知将连带删除多少个分区与网站；至少保留一个页面。
- 删除当前页面后自动切换到仍然存在的页面。

### 2.2 自定义分区

- **新建分区有三处入口**：侧栏任意页面右键 →「新建分区」（在非当前页上操作会先切过去）、
  分区「更多操作」菜单、以及空页面的引导按钮。分区图标与主题色可自定义，不硬编码任何分区名。
- **数量上限**：每个导航页面最多 **4 个分区**，每个分区最多 **12 个网站**（约一屏高度）。
  达到上限后入口会被禁用并说明原因，而不是点了才报错。上限**只拦新增**——
  已有数据（历史配置、导入的备份）即使超限也原样保留，只是不能再往上加。
- **页面主体是响应式多列卡片布局**：每个分区是一张独立的白底圆角卡片，
  高度由内容决定（不被同行的其它卡片拉平），卡片之间保留固定间距。
  列数按**可用宽度**自适应（不是视口宽度）：< 650px 一列，650 / 1000 / 1400px 起依次 2 / 3 / 4 列。
  因为量的是「扣掉侧边栏、再被内容最大宽度封顶」后的真实可用宽度，
  隐藏侧边栏提高列数的效果会自动生效，无需额外判断。
  实现用 CSS 容器查询（`@container`，Chrome ≥ 105，manifest 要求 114）。
- 分区卡片标题栏只保留：拖拽手柄、折叠/展开、分区图标、名称、网站数量、更多操作。
  编辑 / 上移 / 下移 / 删除等低频管理动作全部收进「更多操作」菜单，标题栏不挂一排按钮。
  标题栏高度固定，悬停出现的按钮不会把标题文字顶得位移。
- 分区卡片底部固定有「添加网站」入口，不必先展开操作按钮。
- **拖拽手柄是独立的元素**（卡片顶部最左侧的三横线），标题栏上的按钮不会触发拖拽。
- **分区删除必须确认**；分区内存在网站时，明确提供三种选择：
  1. 同时删除分区及其中的网站；
  2. 把网站移动到其它分区（会显示目标分区所属页面与网站数）；
  3. 取消（不改动任何数据）。
- 选区选择器按导航页面分组展示，跨页面移动时会提示该分区属于其它页面。

### 2.3 网站卡片

- 字段：名称（必填）、地址（必填）、描述、图标、所属分区、打开方式。
- 地址处理：自动去首尾空格、缺协议自动补 `https://`、**拒绝 `javascript:` / `data:` / `file:` 等危险协议**。
- 支持「快捷添加当前网页」：通过 `chrome.tabs` 读取当前标签页标题与地址并预填表单。
  **入口只有顶部「添加 → 添加网站」一个**（搜索框旁原有的 `+` 与它是同一个动作，已移除）。
- 分区内的网站是**紧凑的纵向列表条目**（图标 + 名称 + 域名/描述），不是大尺寸卡片。
  条目高度 44–52px（关闭描述时由行高下限兜底，避免点击区域过小），图标 32px。
- 条目交互：单击打开、`Enter` / `Space` 打开、右键菜单、收藏、编辑、删除、拖拽排序。
- 操作按钮默认隐藏，鼠标悬停或键盘聚焦时才出现；触屏设备上常显。
- 收藏标记（左侧细色条 + 星标）默认克制显示，悬停该条目时才完全凸显。
- 名称始终单行显示，过长时省略；描述是否显示由设置控制（关闭后改显示域名）。
- 条目内所有操作按钮都阻止了冒泡，**拖拽或点击按钮不会误触打开网站**。
- 网址重复时给出提示并允许继续（行为一致，不静默拦截）。

### 2.4 图标策略

按以下顺序逐级降级，任何一级失败都不影响卡片显示：

1. 用户手动指定的图标地址（`iconType = url`）
2. 用户选择的首字母图标（`iconType = text`，完全不发网络请求）
3. `chrome.favicon` 私有 API（扩展的 favicon 缓存，需 `favicon` 权限）
4. 站点自身 `/favicon.ico`
5. 第三方 favicon 服务（**默认关闭**，可在设置中开启；开启前不会向任何第三方服务发起请求）
6. 本地生成的首字母彩色图标（永不失败）

> 第 4 步是目标站点自己的 favicon，不是第三方服务；断网时它同样会失败，
> 于是直接落到第 6 步的本地首字母图标，**任何情况下都不会出现空白方块**。

### 2.5 搜索

- 顶部搜索框同时承担三件事：本地导航搜索、直接打开网址、调用搜索引擎。
- 它是顶栏最显眼的组件（最大宽度 560px，随可用空间自适应），但不占满整条工具栏；
  搜索引擎选择器作为输入框的前置部分，搜索按钮紧邻输入区。
- 本地搜索范围：网站名称、网址、描述、分区名称、页面名称；结果按名称 > 网址 > 描述打分排序，
  并显示所属页面与分区，点击即在对应打开方式下打开。
- 内置搜索引擎：Google、Bing、百度、DuckDuckGo、GitHub（`gh`）、MDN（`mdn`）、npm（`npm`）。
  支持 `gh vue` 这种「关键词前缀切换引擎」写法。
- **搜索词不会自动上传**；只有你主动回车或点击搜索时，才跳转到所选搜索引擎。
- 搜索历史仅保存在本地，可单条删除或一键清空。

### 2.6 收藏与最近访问

- 条目星标即收藏；顶部「更多 → 收藏 / 最近访问」面板可集中查看与取消收藏。
- 该面板**不再常驻顶栏**，也支持点击空白处或 `Esc` 关闭。
- 最近访问**只记录由本扩展主动打开的网站**，不采集浏览器历史、不监控其他标签页。
- 可清空最近访问记录；保留条数可在设置中调整。

### 2.7 拖拽排序与批量管理

- 支持：导航页面排序、分区排序、分区内网站排序。
- 拖拽过程中有占位反馈；拖拽结束后立即保存新顺序，刷新后保持不变。
- 触屏 / 小屏设备提供等价替代：右键菜单或「更多操作」中的上移 / 下移，以及「移动到其它分区」。
- 跨分区移动通过「移动到其它分区」菜单完成（更可控，也便于键盘操作）。
- 批量模式支持：全选本页、按分区全选、批量移动分区、批量收藏/取消收藏、批量设置打开方式、批量删除。
- 批量操作工具条实时显示选中数量，批量删除前二次确认，随时可退出批量模式取消未提交的选择。
- 批量入口在「更多 → 批量管理网站」，不常驻顶栏；进入批量模式后工具条才出现。

### 2.8 设置

**设置只有一个入口**：侧边栏底部的「设置」。顶部工具栏始终保留侧边栏开关，
所以隐藏侧边栏后依然是一步可达，不会出现进不去的死角。

单面板分组（外观 / 背景与样式 / 行为 / 数据管理），所有设置即时生效并持久化：

- **外观**：浅色 / 深色 / 跟随系统、**侧边导航栏位于左侧或右侧**（两者都是纯图标按钮，
  悬停显示名称）、卡片紧凑程度（紧凑/标准/宽松）、是否显示网站描述、是否显示侧边栏、
  是否显示时钟与日期。
- **背景与样式**：纯色 / 渐变 / 背景图片、面板不透明度、卡片圆角。颜色与滑块**拖动时即时预览，
  停手 250ms 才落盘**（避免每一帧都写一次存储）。
- **背景图片支持两种来源**：上传本地图片（等比压缩到最长边 1920 的 WebP data URL，
  存在本地配置里，**不经过任何服务器**），或粘贴远程图片地址。
  上传的图会随导出/导入一起走；远程地址则在每次打开新标签页时请求一次。
- **行为**：默认打开方式、默认搜索引擎、右键菜单开关、快捷键开关、最近访问开关、
  搜索历史开关、是否允许远程 favicon、最近访问保留条数。
- **数据管理**：数据统计、存储占用、导出、导入、清空最近访问、清空搜索历史、
  恢复默认配置、清空全部导航数据（全部危险操作均二次确认）。

#### 侧边导航栏：位置与显示

**位置**：在「设置 → 外观 → 导航栏位置」中可选 **左侧**（默认）或 **右侧**，切换后立即生效并持久化：

- 实现方式是容器上的 `flex-direction: row-reverse`，侧边栏始终是 DOM 的第一个子元素，
  **切换位置不会重建组件**，因此拖拽实例（SortableJS）与滚动位置都不会丢失。
- 分隔线、隐藏按钮的箭头指向都会随位置自动调整。

**显示 / 隐藏**：顶部工具栏最左侧的按钮、侧边栏顶部的箭头、快捷键 `Ctrl/⌘ + B`
是**同一个开关**，三处都能切换，状态写入 `chrome.storage.local`，
重新打开新标签页后保持上次的选择。

- 侧边栏宽度 184px，白底，与主体之间只用一条浅灰分隔线区分。
- 隐藏后主内容区自动占满整宽，**不留任何占位空白**；分区的列数会随之增加。
- 隐藏用 CSS（`display: none`）而非条件渲染，组件不会重建，拖拽实例与滚动位置都不会丢。
- 侧边栏隐藏时仍可通过顶部工具栏的**页面选择器**切换页面；设置则通过工具栏的侧栏开关
  一步唤回侧栏后进入（设置刻意只保留这一个入口，避免同一功能在顶栏与侧栏各出现一次）。

响应式：宽度 < 900px 时侧边栏自动收成图标条；< 760px 时改为放在工具栏下方独占一行
（此时左右位置设置不再影响视觉效果，属预期行为）。

### 2.9 快捷键

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl/⌘ + K` | 聚焦搜索框 |
| `/` | 聚焦搜索框 |
| `Esc` | 清空搜索 / 关闭菜单与弹窗 |
| `Ctrl/⌘ + B` | 显示 / 隐藏导航栏 |

### 2.10 导入 / 导出

- 导出：完整 JSON 备份，包含全部页面、分区、网站、设置与配置版本号。
  **最近访问记录默认不导出**，需要显式勾选，勾选时会说明其中包含访问过的网址。
- 导入前完整校验：文件大小上限（5 MB）→ JSON 格式 → 配置版本 → 顶层结构 →
  字段与类型 → ID 重复 → 页面/分区/网站关联关系 → 网址协议 → 数量与字段长度上限。
- 提供明确的导入策略（覆盖导入 / 取消），覆盖前二次确认并建议先备份。
- **校验不通过时不会清空或改动现有数据。**

## 三、权限说明

| 权限 | 用途 | 是否必需 |
| --- | --- | --- |
| `storage` | 使用 `chrome.storage.local` 保存导航配置与设置 | 必需 |
| `tabs` | 「快捷添加当前网页」「在新/当前标签页打开网站」需要读取与更新标签页 | 必需（仅在你点击时调用） |
| `favicon` | 读取 Chrome 本地 favicon 缓存（`/_favicon/`），避免依赖第三方图标服务 | 可选能力；关闭远程图标后依然可用 |

**未申请**的高危权限（有意为之）：`history`、`browsingData`、`cookies`、`webRequest`、
`declarativeNetRequest`、`downloads`、`management`、`proxy`、`topSites`、`geolocation`，
以及任何 `host_permissions`（即不需要"读取你在所有网站上的数据"）。

CSP 为 `script-src 'self'; object-src 'self'`，不使用 `eval` / `new Function`，
不加载任何远程脚本、样式或字体。`npm run verify` 会自动检查以上各项。

## 四、技术栈与项目结构

### 4.1 技术栈

| 类别 | 选型 | 说明 |
| --- | --- | --- |
| 扩展规范 | Manifest V3 | `chrome_url_overrides.newtab` + Service Worker |
| 框架 | Vue 3.5（`<script setup>` + Composition API） | 无 Options API |
| 语言 | TypeScript 5.9（`strict`） | 无 `any`，无 `@ts-ignore` |
| 构建 | Vite 7 | `base: './'`，manifest 与静态资源放 `public/` |
| 拖拽 | SortableJS | 页面 / 分区 / 卡片排序 |
| 样式 | 原生 CSS + CSS Variables | 主题、密度、圆角均由变量驱动 |
| 图标 | 内置本地 SVG 路径集 | 不依赖任何远程 sprite 或图标字体 |

**关于组件库的取舍（重要）**：任务书建议使用 TDesign Vue Next。实际评估后未采用，原因有三：

1. TDesign 的 `<t-icon>` 采用 svg-sprite 方案，symbol 由**远程脚本**
   （`https://tdesign.gtimg.com/icon/.../index.js`，路径写死在库内）注入。
   MV3 的扩展页面 CSP 会拦截远程脚本，结果是**所有图标空白**；要修复必须额外内联一份
   近 1 MB 的图标 sprite，收益与体积不成正比。
2. 本项目的核心 UI（卡片网格、分区面板、右键菜单、拖拽列表）本身就是定制组件，
   组件库能覆盖的部分有限，引入后仍需大量 `:deep()` 覆盖样式。
3. 任务书同时要求「控制依赖数量」「不得运行时依赖 CDN」。自建轻量组件
   （弹窗、确认框、提示、图标）约 600 行，零运行时依赖、完全离线、便于维护。

后来为改善设置面板观感，引入了 **Naive UI**（`naive-ui@2.45`）并渐进式迁移：
Naive UI 无独立 CSS 文件（运行时 CSS-in-JS 注入，无任何远程资源请求，兼容 MV3 CSP），
品牌色/圆角/字体经 `useNaiveTheme.ts` 对齐到项目的 CSS 变量体系。
目前已迁移**设置面板**（NModal + NTabs 分组），其余自建组件按需逐步迁移；
运行时依赖为 `vue`、`sortablejs`、`naive-ui` 三项。store / service 分层与组件库无关，
视图层可继续替换。

### 4.3 数据模型

```ts
NavigationPage { id, name, icon, order, createdAt, updatedAt }
```

数据约束：

- 所有实体使用稳定唯一 ID（`前缀_时间戳36进制+序号+随机串`），**不使用数组下标**。
- 排序使用独立的 `order` 字段，重排后连续化；不依赖对象遍历顺序。
- 删除页面/分区时显式处理关联网站（级联删除或迁移），不会静默丢数据。
- 通过 `schemaVersion` 管理配置版本，`repository.ts` 中保留完整迁移骨架。
- 加载时执行完整性修复（孤立分区/网站、非法 URL、失效关联、order 连续化），
  并把修复结果告知用户。

### 4.4 存储方案

- 物理上只有**一个** `chrome.storage.local` 键：`mynavi:state`，其中保存整份配置文档。
  导航配置体量很小，整体读写换来两个关键收益：**写入原子**（不会出现只更新一半的中间态）
  与**读取路径唯一**（不存在多键映射歧义）。
- **向后兼容读取**：历史构建曾把数组序列化成以数字为键的对象
  （`"pages": {"0":{…},"1":{…}}`）。读取时会自动识别并还原为数组，
  不会把这类完全正常的配置误判为"数据损坏"；下次写入时自动按数组格式回写。
  `npm run legacy` 专门锁定这条路径。
- **只读保护**：如果已保存的数据**确实无法解析**，应用会进入只读保护模式——
  绝不写入任何内容，避免用空状态覆盖用户数据；同时给出具体原因与
  「重新读取」入口。只有用户在二次确认后显式执行「导入 / 恢复默认 / 清空数据」，
  才会解除保护并写入。`npm run corrupt` 专门验证这一点。
- 所有写操作走串行队列；状态未变化时完全不写存储。
- 写操作采用「乐观更新 + 失败回滚」：写入失败会把内存状态恢复为操作前的快照，
  保证界面与磁盘始终一致，并给出包含处理建议的错误提示。
- 每个写操作统一返回 `Result`，**存储层从不抛异常**。
- 普通网页预览时自动回退到 `localStorage`，因此 `npm run dev` 也能完整调试。

## 六、已知限制

1. **未实现合并式导入**。导入只有「覆盖现有配置」与「取消」两种策略，符合任务书第一版范围；
   导入前会展示即将写入的页面/分区/网站数量，并建议先导出备份。
2. **跨分区拖拽未启用**。分区内排序稳定可靠；跨分区移动通过右键菜单的
   「移动到其它分区」完成，在触屏与小屏设备上同样可用（这是任务书允许的取舍）。
3. **窄屏（< 900px）下侧边栏自动收成图标条**，更窄时侧栏在工具栏下方换行；
   未实现抽屉式侧栏。主内容区按容器宽度自适应列数，不产生横向滚动条。
4. **多列卡片用 CSS Grid，不做瀑布流**。Grid 会把同一行的卡片按该行最高的那张对齐，
   因此同行内较矮的卡片下方会有留白。真瀑布流（CSS `columns` 或 masonry 库）能消除留白，
   但 `columns` 是「先竖后横」的排版顺序，会让拖拽排序的视觉顺序失去意义，
   故按取舍选择 Grid + `align-items: start`（卡片保持自身高度、不被拉伸）。
5. **拖拽排序在自动化测试中没有覆盖**。所有测试脚本都不模拟拖放
   （原生 HTML5 拖放也无法由 CDP 合成鼠标事件驱动），因此手柄与排序行为
   只在真实浏览器中手动验证过。已实测的是「拖分区主体不触发排序」这一负向用例。
6. **设置只有侧边栏一个入口**。这是刻意的去重结果：工具栏始终保留侧栏开关，
   所以隐藏侧栏后设置只需一步唤回。若希望隐藏侧栏时也能直达设置，需要额外加回顶栏入口，
   但那会与「设置入口只保留一个」的要求冲突。
7. **搜索框旁的「快捷添加当前网页」按钮已移除**，因为它与「添加 → 添加网站」
   调用的是同一个方法，属同一功能的重复入口。
8. **`chrome.favicon` 依赖 Chrome 的 favicon 缓存**，缓存未命中时按第 2.4 节的顺序降级；
   首次访问某站点前可能出现首字母图标，属预期行为。个别站点提供的 favicon 本身是
   近乎透明的极小图片，此时会回退为首字母图标。
9. **旧版格式只做读取兼容，不主动回写**。识别到"对象映射"格式后，数据会以数组形式
   在内存中使用；要等下一次编辑才会按新格式回写存储（避免仅打开新标签页就产生写入）。
10. **只读保护是"失败即冻结"策略**。一旦读取失败，所有编辑操作都会被拒绝并提示原因；
   这是刻意的数据安全取舍——宁可不写入，也不覆盖用户数据。
11. **服务端/浏览器差异**：以当前稳定版桌面 Chrome（≥ 114）为目标，
   Windows 平台已实测加载与运行；未针对 Firefox 适配（但代码未使用 Chrome 专有语法之外的耦合）。
   容器查询（`@container`）要求 Chrome ≥ 105，低于 manifest 声明的 114。
12. **沙箱环境下 esbuild 无法启动**时的安装说明见下节。

## 七、离线与受限环境

### 7.1 依赖清单（运行时不依赖其中任何一项的远程资源）

开发与构建依赖（`devDependencies`）：`vite`、`@vitejs/plugin-vue`、`typescript`、`vue-tsc`、
`@types/node`、`@types/chrome`、`@types/sortablejs`。
运行时依赖（`dependencies`）：`vue`、`sortablejs`。全部随扩展一起打包，`dist/` 中不含任何远程引用。

### 7.2 若 `npm install` 因生命周期脚本失败

在受限沙箱中，npm 执行依赖的 `postinstall` 脚本时会因无法创建管道而报 `spawn EPERM`
（典型出现在 `esbuild` 的 `install.js`）。此时可用：

```bash
npm install --ignore-scripts
```

`esbuild` 的 Windows 预编译二进制由可选依赖 `@esbuild/win32-x64` 提供，无需 `postinstall` 即可工作；
可用以下命令确认：

```bash
node tools/check-esbuild.mjs      # 期望输出：esbuild transform OK: const a = 1;
```

### 7.3 完全离线构建

1. 在可联网机器上执行 `npm install`（生成 `package-lock.json`）与
   `npm install --offline` 验证缓存完整性；
2. 将整个 `node_modules/` 与 `package-lock.json` 一并拷贝到离线机器；
3. 离线机器上直接执行 `npm run build`（无需再次联网）。

若使用代理或私有 registry，请在项目根目录新建/修改 `.npmrc` 后重新安装。

## 八、隐私与安全声明

- 所有导航数据、设置、搜索历史与最近访问**只保存在本机浏览器扩展存储中**，
  不上传、不同步、不联网备份。
- 不申请浏览历史、Cookie、网络请求拦截、地理位置等权限；不监控你的浏览行为。
- 仅在**你主动点击**「快捷添加当前网页」时读取一次当前标签页的标题与地址。
- 只有你主动回车或点击搜索时，才会跳转到所选搜索引擎；搜索词不会在后台被发送。
- 扩展不加载任何远程脚本、样式或字体；可选的第三方 favicon 服务可在设置中一键关闭。
- 导入的配置文件一律视为**不可信输入**，完整校验通过后才会写入；
  打开任何网址前都会再次校验协议，拒绝 `javascript:` 等危险协议。
- 界面不使用 `v-html` 等不安全渲染方式展示网站名称与描述，不存在 HTML 注入面。

## 九、常见问题

**Q：图标全是空白或首字母？**
A：Chrome 的 favicon 缓存需要"访问过该站点"才有数据，新安装或清理缓存后可能命中不到。
可在设置中保持「允许请求远程网站图标」开启；或编辑网站卡片手动指定图标地址。

**Q：新标签页没有变成 SeqPage？**
A：请确认安装的是 `dist/` 目录，并检查 `chrome://extensions/` 中是否有报错；
其他扩展也可能占用了新标签页覆盖，需要先停用冲突扩展。

**Q：设置改完没生效？**
A：设置即时保存。若顶部出现红色错误横幅，说明存储写入失败（例如空间已满），
提示中会说明处理方式；此时可先导出备份。

**Q：提示"本地保存的配置无法解析"，我的数据丢了吗？**
A：没有丢。出现这条提示说明**读取**失败，此时应用会进入**只读保护**：
不写入任何内容，磁盘上的原始数据保持原样。请按提示先点「重新读取」；
若仍然失败，你的原始数据仍在扩展存储里。1.0.0 之前的构建曾把数组存成
以数字为键的对象（`{"0":{…}}`），当前版本已能自动识别并还原这种格式，
不会再误判为损坏。

**Q：怎么排查"配置没有恢复"？**
A：在扩展页面的开发者工具控制台执行 `__MYNAVI__.bootTrace()`，可以看到本次启动
读取到的页面数、网站数、主题以及采用的是「读取已保存配置」还是「初始化演示数据」；
`__MYNAVI__.backend` 显示存储后端，`__MYNAVI__.writeProtected` 显示是否处于只读保护。

**Q：拖动卡片时会误打开网站吗？**
A：不会。拖拽期间会给 `body` 加上 `is-dragging` 标记并禁用卡片内部元素的指针事件，
拖拽结束也不会触发点击。
